## 🖤 The Big Idea (box it, centre of page)
> **Most problems arrive as someone's solution. Negotiate back to the real need, harden it with facts, compare at least three options, then write down what worked so it repeats.**
> (Samuel & Weir, 1999, Ch. 6 · RedVectorOnline, 2016)

## 🖤 Zone 1 - From need to specification (R1b)
```
NEED -> DESIGN GOAL -> TECHNICAL OBJECTIVES + LIMITS -> ALTERNATIVES -> DECISION -> SPEC
  forward chaining  ------------------------------------------------>
  <------------------------------- backward chaining: "what is the real essence of the problem?"
```
- 🔵 **Need-directed** = vague, goals unspoken · **Goal-directed** = goal named. No design until goals are agreed.
- 🔴 **Trap:** a solution-oriented brief ("build a better mousetrap") limits the search more than anything else.

## 🖤 Zone 2 - Harden the information (R1b)
| Hard | Soft | Content-free |
|---|---|---|
| measured, comparable | "too many road deaths" | "public transport is inefficient" |
| use it to size effort | harden it with data | avoid it |
- 🔵 **Enformulation:** map the soft problem onto technical objectives through **islands of certainty**: data, budget, mandatory constraints, windows of opportunity (the bicycle-theft example).
- 🔴 **My version:** "the data is messy" is content-free. "One live report view lost some Semester 1 rows" is hard.

## 🖤 Zone 3 - Failure and models (R1a)
- 🔵 **The model is not the thing:** Tacoma Narrows (twisting nobody modelled), Comet (fatigue at window corners).
- 🔵 **Failure types:** technical (missing information) · operational (wrong use) · unpredictable (special circumstances).
- 🔵 **Failure intensity** = economic, environmental, social impact. Higher intensity, stronger incentive to prevent.
- 🔴 Study failures for the **technical cause**, not for blame.

## 🖤 Zone 4 - Make the model visible (R2)
```
nodes (things, people) + links (connections) = systems model
alone, paper: 4-8 nodes  ->  alone, cards: more, clearer  ->  group, cards: 20+, aligned
```
- 🔵 **5 to 13 nodes** for a diagram others must read. Over 13 = "map shock".
- 🔴 The **conversation** matters more than the drawing. Build the model *with* the stakeholder.

## 🖤 Zone 5 - The eight steps + OODA (R3) ⭐ the tool for Activity 1 and A2
```
1 Clarify (what/where/when/who/why/how/impact) -> 2 Data + gap -> 3 Target -> 4 Root cause (5 whys)
-> 5 THREE options -> 6 Implement + measure -> 7 Confirm (loop back) -> 8 Standardise (SOP)
OODA: observe -> orient -> decide -> act
```
- 🔴 **Step 8 is the most skipped.** My SOP is the written award rules note, versioned in Phase 2.

## 🔴 If you only memorise 5 things
1. **What you want is not necessarily what you need.** Chain back to the essence.
2. **Soft → hard:** find the islands of certainty before choosing.
3. **The model is not the thing.** A fresh view is not a complete one.
4. **Three options, judged on effectiveness, feasibility and impact.**
5. **Standardise:** if it worked, write the SOP.
